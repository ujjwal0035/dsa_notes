# Backtracking — Problem Solving & Pattern Tracker

**Purpose:** Detailed, interview-oriented tracker for backtracking. Every hard/backtracking problem should be recorded through the same reasoning flow so the reusable pattern is clear.

## Mandatory learning flow

1. **Question** — understand exactly what must be generated/found.
2. **Pattern identification** — identify the backtracking pattern before coding.
3. **Logic discussion** — define state, choices, validity/pruning, base case, and what must be undone.
4. **Implementation** — Java solution.
5. **Review** — correctness, edge cases, complexity, and mistakes.
6. **Pattern note** — write the reusable template in plain language.
7. **Rating** — update problem/pattern skill when enough evidence exists.
8. **Git update** — append the problem and update priorities.

# Master Backtracking Framework

```text
State
 ↓
Base Case?
 ↓ no
Generate Choices
 ↓
Check Validity / Prune
 ↓
Choose
 ↓
Explore / Recurse
 ↓
Undo
```

### Four questions to ask first
1. What is my state?
2. What is my base case?
3. What choices do I have?
4. What must I undo after recursion?

### Common patterns
- Take / Skip
- Pick any unused item
- Choose from current index onward
- Reuse current choice
- Constraint-based construction and pruning

# Solved Problem 1 — Subsets

**LeetCode:** 78. Subsets

### 1. Question
Generate every subset of an array of unique integers.

### 2. Pattern identification
**Pattern:** Take / Skip binary backtracking.

### 3. Logic discussion
At index `i`, two choices exist:
```text
Take nums[i]
Skip nums[i]
```
Base case:
```text
i == nums.length
```
At the base case, copy the current path into the result.

### 4. Implementation
User used a mutable `List<Integer>` and removed the last element after the take branch.

### Special case
The empty subset is a valid answer, so it is naturally generated by skipping every element.

### Rating
**5/5**

### Pattern to remember
> When every element has an independent include/exclude decision, think binary backtracking.

# Solved Problem 2 — Permutations

**LeetCode:** 46. Permutations

### 1. Question
Generate all permutations of an array of unique integers.

### 2. Pattern identification
**Pattern:** Pick any unused element at each level.

### 3. Logic discussion
State:
```text
current path + used elements
```
Choices:
```text
any index not already used
```
Base:
```text
path.size() == nums.length
```
Undo:
```text
remove last element
visited[i] = false
```

### 4. Implementation
The user first used `path.contains(nums[i])`, then improved to `boolean[] visited`, which gives constant-time usage checks.

### Rating
**5/5**

### Pattern to remember
> Permutations usually mean: choose any unused element, recurse, then unchoose it.

# Solved Problem 3 — Combination Sum

**LeetCode:** 39. Combination Sum

### 1. Question
Find combinations of candidates that sum to target; a candidate may be reused unlimited times.

### 2. Pattern identification
**Pattern:** Choose from current index onward + reuse current choice.

### 3. Logic discussion
For loop starts at `idx` to avoid generating different orderings of the same combination.
When choosing `nums[i]`, recurse with `i`, not `i+1`, because the same candidate may be reused.

Base cases:
```text
sum == target → store answer
sum > target → prune
```

### 4. Implementation
Mutable path + sum + index; choose → recurse → remove and restore sum.

### Special case
The same combination must not appear in different orders.

### Rating
**5/5**

### Pattern to remember
> If reuse is allowed, recurse with the same index; if each element can be used once, advance the index.

# Solved Problem 4 — Generate Parentheses

**LeetCode:** 22. Generate Parentheses

### 1. Question
Generate all valid strings containing `n` pairs of parentheses.

### 2. Pattern identification
**Pattern:** Constraint-based backtracking / generate only valid prefixes.

### 3. Logic discussion
State:
```text
openCount
closeCount
current string
```
Choices:
```text
Add '('
Add ')'
```
Validity:
```text
openCount < n
closeCount < openCount
```
Base:
```text
openCount + closeCount == 2*n
```
The close-parenthesis constraint prevents invalid prefixes from ever entering the recursion tree.

### 4. Implementation
User used `StringBuilder`, append before recursion, and `deleteCharAt` after recursion.

### Special insight
The validity check can be simplified from a helper to:
```text
if (closeCount < openCount)
```

### Complexity
Proportional to the number of valid Catalan combinations, with O(n) recursion depth.

### Rating
**5/5**

### Pattern to remember
> In constrained generation problems, prune invalid partial states instead of generating everything and validating afterward.
